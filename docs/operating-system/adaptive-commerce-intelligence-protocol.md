# Adaptive Commerce Intelligence Protocol

**Status:** LOCKED
**System:** Sonic AI V3 / Omega House Commerce Intelligence
**Scope:** Shopify ecommerce engineering, music-commerce operations, experiments, audits, product systems, and measurable business outcomes

## Purpose

This protocol defines the human-AI operating loop used to progressively discover, understand, validate, improve, document, and monetize the Omega House commerce system.

The objective is not to produce a static audit or a collection of prompts. The objective is to create a continuously improving intelligence loop in which every meaningful action produces evidence, every useful discovery changes the next decision, and validated improvements create measurable leverage.

## Core Loop

```text
LISTEN
  ↓
MEDITATE
  ↓
RE-LISTEN
  ↓
TAKE NOTES
  ↓
Q&A
  ↓
REPEAT
  ↓
ADAPT THE PROMPT
  ↓
ACTIONABLE EVENT
  ↓
MEASURE
  ↓
PAYOUT
  ↓
LEARN
  ↺
```

### 1. LISTEN

Receive the objective, evidence, constraints, history, timing, and intended outcome without prematurely committing to an implementation.

### 2. MEDITATE

Separate what is known from what is assumed. Identify contradictions, missing evidence, dependencies, risks, and potentially higher-value questions.

### 3. RE-LISTEN

Re-evaluate the original request against the larger Omega House system, Shopify capabilities, customer journey, music-production business model, prior performance, technical architecture, and long-term intent.

### 4. TAKE NOTES

Record structured intelligence:

- facts
- assumptions
- variables
- dependencies
- observations
- opportunities
- risks
- questions
- decisions
- evidence
- expected outcomes
- actual outcomes

### 5. Q&A

Interrogate the highest-value unknowns before implementation. Questions should become more precise as evidence accumulates.

### 6. REPEAT

Run the loop again using the newly acquired knowledge. The protocol is intentionally recursive.

## Adaptive Prompt Rule

The prompt is a living control surface rather than a fixed instruction.

```text
Prompt vN
   ↓
Observation
   ↓
Intelligence
   ↓
New Variables
   ↓
Questions
   ↓
Revised Prompt vN+1
   ↓
Action
```

The next prompt may change when new evidence, customer behavior, technical constraints, business objectives, timing, or previous decisions change the problem.

A prompt is considered successful when it produces better decisions and more actionable outcomes, not merely better prose.

## Actionable Event Standard

An actionable event must have:

- objective
- current state
- desired state
- owner
- dependencies
- completion criteria
- expected timing
- measurement method
- expected business impact
- validation method
- next transition

Where possible, events should connect:

```text
ACTION → MEASUREMENT → LEARNING → OPTIMIZATION → PAYOUT
```

A payout may be financial or strategic. Examples include revenue, conversion improvement, qualified leads, product consumption, customer retention, reusable infrastructure, new intelligence, time saved, validated hypotheses, new products, or partnership leverage.

## Pinnacle Rule

A **PINNACLE** is a verified point at which a specific future intent or present goal has reached its defined successful state within the expected outcome window, or has otherwise achieved an explicitly approved equivalent outcome.

A Pinnacle is not declared because work feels complete. It requires evidence.

### Pinnacle conditions

Before declaring a Pinnacle, evaluate:

1. **Intent** — What exact future or present objective was being pursued?
2. **Expected timing** — What outcome window was established?
3. **Definition of success** — What observable state constitutes completion?
4. **Evidence** — What proves the state has been reached?
5. **Variance** — What differed from the original expectation?
6. **Payout** — What measurable value was created?
7. **Succession** — What objective logically follows from this completed state?

### Pinnacle Lock

When all required conditions are satisfied:

```text
VERIFY
  ↓
DECLARE PINNACLE
  ↓
CAPTURE EVIDENCE
  ↓
COMPARE FORECAST vs ACTUAL
  ↓
RECORD PAYOUT
  ↓
EXTRACT LEARNING
  ↓
CLOSE THE OBJECTIVE
  ↓
CREATE SUCCESSOR INTENT
  ↓
ADVANCE
```

The completed objective becomes historical evidence and must not be casually reopened unless new evidence materially changes the underlying assumptions.

### Succession principle

Every genuine Pinnacle should create a **successor state** when the larger mission continues.

The successor should inherit the useful context of the completed objective while explicitly defining what is new.

```text
INTENT A
  ↓
EXECUTION
  ↓
PINNACLE A
  ↓
LEARNING A
  ↓
SUCCESSOR INTENT B
  ↓
EXECUTION
  ↓
PINNACLE B
```

This prevents the system from confusing perpetual optimization with progress. Completion must be recognized, measured, archived, and converted into the next strategically justified objective.

## Timing Intelligence

Expected timing is part of the objective, not an afterthought.

For each meaningful future intent, record:

- target date or time window
- confidence level
- assumptions behind the forecast
- leading indicators
- milestone states
- actual completion date
- variance from expectation
- cause of variance
- lessons for future forecasting

Over time, these records should improve Omega House's ability to forecast realistic completion and business outcomes.

## Documentation and Intelligence Persistence

GitHub is the canonical engineering/documentation substrate for the Sonic AI V3 system.

The commerce intelligence process should produce durable records suitable for both human review and future machine retrieval.

Documentation should preserve:

- decisions
- rationale
- evidence
- experiments
- measurements
- outcomes
- timing
- failures
- successful patterns
- reusable procedures
- unresolved questions
- successor objectives

The resulting knowledge should become usable input for Sonic's memory, knowledge, event, agent, analytics, and intelligence layers.

## Commerce Intelligence Architecture

The long-term flow is:

```text
Shopify / Customer / Product / Storefront Events
                 ↓
          Evidence + Analytics
                 ↓
       Commerce Intelligence
                 ↓
        Human + AI Reasoning
                 ↓
        Decision / Experiment
                 ↓
         Actionable Event
                 ↓
          Business Outcome
                 ↓
       Measurement + Payout
                 ↓
        Persistent Memory
                 ↓
          Better Next Prompt
                 ↺
```

The immediate implementation priority is to establish trustworthy evidence before automation. The Test Data Shopify theme is therefore treated as a controlled laboratory, with Horizon as a modern architectural reference and the production storefront as the empirical baseline.

## Operating Principle

> **Do not optimize the wrong layer.**

If the offer is wrong, do not solve it with JavaScript.

If the UX is wrong, do not solve it with unnecessary apps.

If performance is wrong, do not solve it with visual decoration.

If measurement is unreliable, do not build intelligence on corrupted data.

If the problem is not understood, do not manufacture certainty.

The system advances through evidence, disciplined iteration, measurable outcomes, and verified completion.

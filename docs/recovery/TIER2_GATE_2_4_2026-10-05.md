## Objective

Make explicitly materialized intelligence memory useful to Sonic without adding opaque semantic claims or remote data exposure.

## Retrieval contract

Inputs:
- query text
- optional intent scope
- bounded result limit

Eligible corpus:
- memory candidates only
- explicitly materialized
- candidate still accepted

Ranking is deterministic and explainable:

`score = 0.55 token_coverage + 0.20 confidence + 0.15 evidence_strength + 0.10 exact_phrase`

Eligibility threshold:
- exact phrase match, or
- at least 40% query-token coverage

This prevents weak one-token matches from polluting multi-token queries.

Each result returns:
- matched tokens
- token coverage
- exact-phrase flag
- confidence contribution
- evidence-strength contribution
- final score
- method identifier

This is deliberately a transparent lexical/evidence baseline, not a claim of semantic understanding.

## Access boundary

- Local authenticated Workbench HTTP may retrieve.
- Local MCP exposes a read-only `sonic_intelligence_retrieve` tool.
- OAuth/public MCP mode is denied for intelligence memory retrieval.
- No retrieval call writes state.

## Gate 2.4 acceptance

- inactive/unmaterialized candidates never retrieve
- relevant active memory ranks deterministically
- scoring explanation matches the result
- HTTP retrieval requires local authentication
- local MCP retrieval succeeds
- public/OAuth MCP retrieval fails closed
- existing MCP registry/security tests remain green

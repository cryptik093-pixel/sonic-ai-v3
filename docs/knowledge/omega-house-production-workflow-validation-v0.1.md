## 1. Purpose

This document records the production workflow that has been developed, repeatedly executed, and materially improved through real Omega House production work.

This is **not yet a final SOP**. It is a versioned validation record intended to preserve observations, production evidence, emerging heuristics, and time progression so Sonic AI can eventually distinguish validated methods from experimental ideas.

Core principle:

> Sonic AI should learn from the relationship between production decisions, processing, deliverables, time, quality, and repeatability — not merely memorize isolated plugin settings.

## 5. Signal-Chain / Volume-Spreading Heuristic

### Observation

Chaining a sample or audio through processing stages can distribute energy across the signal path. With appropriate gain staging, this can reduce concentrated peaks and potentially produce a louder, cleaner perceived result.

### Important constraint

This is a **production heuristic**, not a universal rule. The outcome depends on:

- input gain
- output gain
- transient structure
- compression
- saturation
- limiting
- frequency distribution
- peak level
- RMS/LUFS/perceived loudness
- cumulative gain through the chain

### Sonic AI representation

```text
Audio Input
    ↓
Processing Stage(s)
    ↓
Energy / Peak Redistribution
    ↓
Gain Staging
    ↓
Perceived Loudness + Cleanliness
```

Future experiments should compare before/after peak, RMS/LUFS, transient integrity, and subjective quality.

## 6. Gross Beat Parameter-Relationship Heuristic

### Observation

The producer has identified a useful conceptual relationship between Gross Beat's **Volume** and **Time** controls and the degree to which the original signal is preserved versus transformed.

Attack, Release, and INT are understood as finer-grain controls for dialing the resulting behavior.

The producer describes the interaction conceptually as being similar to **solving a division problem**: relative parameter openness changes the balance between original-signal preservation and time/volume transformation.

### Current classification

**Experimental plugin heuristic — requires controlled validation.**

Sonic AI should store this as a relationship hypothesis rather than as a fixed Gross Beat preset rule.

Potential future model:

```text
Time shaping
      ↕
Original signal preservation
      ↕
Volume shaping
      ↓
Attack / Release / INT micro-adjustment
      ↓
Perceived result
```

The useful intelligence is likely to be the **parameter relationship**, not any single numerical setting.

## 7. Macro DAW Transformation

The producer has identified that macro tools can alter the formatting and digital arrangement of an entire production rather than only individual notes or audio events.

This is particularly useful for:

- MIDI cleanup
- note/event organization
- timing normalization
- arrangement cleanup
- export preparation
- interoperability between systems

The exact methodology for avoiding over-processing or under-processing is still being learned.

### Current classification

**Known capability / developing methodology.**

The target principle is:

> Clean and normalize digital musical information without removing intentional musical information.

This distinction is especially important for Sonic AI because “cleaner” MIDI is not necessarily “better” MIDI.

## 15. Next Documentation Cycle

Capture each significant production discovery using this structure:

1. **Context** — what was being built?
2. **Input** — what source asset/plugin/state was used?
3. **Action** — what changed?
4. **Parameter relationship** — which controls interacted?
5. **Result** — what changed perceptually/technically?
6. **Failure mode** — what went wrong, if anything?
7. **Repeatability** — does it work again?
8. **Deliverable impact** — did it improve MIDI, stems, audio, composition, or packaging?
9. **Time impact** — faster, slower, or neutral?
10. **Confidence** — observed, repeatable, validated, generalized, or automatable?

This becomes the foundation for turning the producer's evolving intuition into structured Sonic AI knowledge.

# Tier 2 — Gate 2.5 Decision Intelligence

**State:** VALIDATION_PENDING  
**Dependency:** Gate 2.4 explainable retrieval  
**Branch:** `tier2/gate-2-5-decision-intelligence-2026-10-05`

## Objective

Answer one operational question deterministically:

> Given the current intent, explicit option factors, verified evidence, and active materialized memory context, which action should be considered next — and why?

This gate ranks actions. It does not execute them.

## Input contract

Each option supplies normalized values from 0–1 for:
- intent alignment
- expected impact
- urgency
- reversibility
- effort
- resource cost
- risk

Each option may cite scoped evidence IDs and declares an authority level:

- `L0_READ_ONLY`
- `L1_LOCAL_REVERSIBLE`
- `L2_EXTERNAL_REVERSIBLE`
- `L3_BUSINESS_MUTATION`
- `L4_IRREVERSIBLE`

## Evidence strength

`evidence_strength = mean(evidence_confidence) × min(evidence_count / 3, 1)`

Evidence IDs must exist in the same intent/workspace or be explicitly global evidence.

## Decision score

Positive components:

- 28% intent alignment
- 24% expected impact
- 16% evidence strength
- 10% urgency
- 10% reversibility
- 12% execution efficiency

Where:

`execution_efficiency = 1 - mean(effort, resource_cost)`

Penalties:

- 18% risk
- authority friction:
  - L0: 0.00
  - L1: 0.01
  - L2: 0.04
  - L3: 0.08
  - L4: 0.15

Scores are clamped to 0–1.

## Decision confidence

`confidence = 0.65 × top_evidence_strength + 0.35 × min(score_gap / 0.20, 1)`

Status rules:

- insufficient evidence → `needs_evidence`
- L4 or risk ≥ 0.80 winner → `manual_review`
- weak confidence or narrow score gap → `provisional`
- otherwise → `recommend`

## Explainability

Output includes:
- complete ranked option list
- score components and penalties
- evidence used per option
- top-vs-runner-up score gap
- component-level advantage breakdown
- authority level and approval requirement
- active materialized memories relevant to the objective

Materialized memory is returned as **context only**. It does not silently alter option scores. Only explicitly cited evidence affects evidence strength.

## Authority boundary

This gate exposes no execution capability.

- HTTP ranking is local authenticated Workbench only.
- MCP ranking is read-only and local-operator-only.
- OAuth/public MCP mode is denied.
- L1–L4 recommendations require explicit approval before any future execution layer.
- L4/high-risk winners are forced to manual review.
- Ranking creates no event, memory, candidate, Shopify mutation, outbound message, payment, or filesystem artifact.

## Gate 2.5 acceptance

- evidence-backed bounded action outranks weaker/high-risk alternatives when formula supports it
- no-evidence winner cannot become a high-confidence recommendation
- cross-intent evidence fails closed
- irreversible/high-risk winner is marked manual review
- materialized memory context cannot secretly change scores
- duplicate option IDs fail closed
- local HTTP/MCP ranking is read-only
- public/OAuth MCP access is denied
- existing MCP registry/security tests remain green

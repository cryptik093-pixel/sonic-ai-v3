# Tier 2 — Gate 2.3 Controlled Materialization

**State:** VALIDATION_PENDING  
**Dependency:** Gate 2.2 persistent intelligence ledger  
**Branch:** `tier2/gate-2-3-controlled-materialization-2026-10-05`

## Objective

Make accepted memory candidates usable without copying them into an unaudited legacy truth store.

## Two-step authority model

1. Candidate decision:
   `proposed → accepted`
2. Separate explicit materialization:
   `accepted → activated memory view`

Acceptance alone is not materialization.

## Reversible read model

Materialization is represented by append-only events:
- `activate`
- `retire`

The effective memory view contains only candidates where:
- latest requested materialization state is active
- candidate type is `memory`
- candidate status is still `accepted`

If an accepted candidate is later superseded, it immediately stops qualifying for the active read model while all history remains intact.

## Integrity rules

- proposed candidates cannot materialize
- non-memory candidates cannot materialize
- exact event replay is idempotent
- materialization event ID reuse with different content fails closed
- a new activation while already active is rejected
- retirement is explicit and auditable
- active memory contains provenance: candidate, intent, evidence IDs, confidence, materialization event trail
- no row is silently copied into legacy `memories`
- no autonomous action authority is created

## Gate 2.3 acceptance

- persistence tests remain green
- materialization tests pass
- authenticated API requires both approval and activation
- retirement removes candidate from the active read model
- supersession removes candidate from the active read model
- broad Sonic CI/security/runtime gates remain green after retargeting to main

## Why this belongs in Sonic AI V3

These documents are not runtime source code. They are the historical knowledge and evidence layer that explains the production philosophy, product architecture, education system, commercial assumptions, and developmental lineage the runtime is expected to serve. They should therefore remain versioned but isolated from executable application code.

## Governance

1. Treat the ZIP as an immutable source artifact.
2. Do not import investor projections or marketing claims into runtime truth without explicit validation.
3. Production doctrine is normative design context; runtime behavior must still be validated by tests and measurable evidence.
4. Historical documents should be cited by filename/version when converted into machine-readable knowledge artifacts.
5. New Phase 2 doctrine changes should be recorded as addenda rather than silently rewriting the Phase 1 historical record.
